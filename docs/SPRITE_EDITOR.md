# Sprite Sheet Editor 개발 문서

## 1. 목적

이 저장소의 Sprite Sheet Editor는 웹 브라우저에서 스프라이트 시트를 불러와 프레임을 분할하고, 프레임별 위치와 크기를 보정한 뒤, 새로운 스프라이트 시트 PNG로 다시 내보내기 위한 정적 웹 도구다.

주요 목표는 다음과 같다.

- 스프라이트 시트를 업로드하면 행/열 기준으로 프레임을 나눈다.
- 자동 추정 또는 수동 입력으로 프레임 크기, 행/열, 오프셋, 간격을 조정한다.
- 출력 순서에서 프레임을 선택, 추가, 제거, 재배치한다.
- 여러 프레임을 동시에 선택해서 위치 보정, 중앙 정렬, 프레임 박스 크기 보정을 적용한다.
- 재생 미리보기로 애니메이션을 확인한다.
- 최종 결과를 스프라이트 시트 PNG로 내보낸다.
- Cloudflare Pages 또는 GitHub Pages 같은 정적 호스팅에서 빌드 없이 동작한다.

## 2. 현재 구조

현재 앱은 빌드 과정이 없는 정적 파일 기반이다.

```text
/
├─ index.html
├─ styles.css
├─ src/
│  ├─ app.js
│  ├─ grid-layout.js
│  └─ frame-box-fix.js
└─ docs/
   └─ SPRITE_EDITOR.md
```

### 핵심 파일

#### `index.html`

- 앱의 화면 구조를 담당한다.
- 분할 설정, 원본 무대, 편집/출력 패널을 포함한다.
- Cloudflare Pages에서 루트 정적 파일로 바로 제공된다.
- 스크립트는 `defer`로 로드한다.

#### `styles.css`

- 전체 레이아웃, 모바일 대응, 프레임 목록 그리드, 버튼 스타일을 담당한다.
- 모바일에서도 출력 순서가 설정 열 수 그대로 보이도록 카드 크기를 자동 축소한다.

#### `src/app.js`

- 대부분의 앱 상태와 편집 로직을 담당한다.
- 이미지 로드, 프레임 분할, 출력 순서, 선택 상태, 위치 보정, 프레임 박스 크기 보정, 미리보기, 재생, PNG 내보내기를 처리한다.

#### `src/grid-layout.js`

- `분할된 프레임`과 `출력 순서` 그리드 열 수를 고정하는 보조 스크립트다.
- 현재 정책은 출력 순서도 원본 분할 설정의 열 수를 따른다.

#### `src/frame-box-fix.js`

- 과거 프레임 박스 크기 보정 문제를 해결하기 위해 추가된 보조 스크립트다.
- 현재 `app.js` 본체에 관련 로직이 통합되어 있으므로, 유지 여부를 검토할 필요가 있다.
- 기능 중복이 확인되면 삭제하거나 `app.js`와 역할을 명확히 분리해야 한다.

## 3. 현재 주요 기능

### 이미지 업로드

- 브라우저 File API로 이미지 파일을 읽는다.
- `Image` 객체로 로드한 뒤 캔버스에 표시한다.
- 업로드 후 자동 추정을 수행한다.

### 프레임 분할

지원 입력값:

- 기본 프레임 너비
- 기본 프레임 높이
- 열 수
- 행 수
- X/Y 오프셋
- X/Y 간격

분할 방식:

```text
sx = offsetX + col * (frameWidth + gapX)
sy = offsetY + row * (frameHeight + gapY)
```

분할된 프레임은 내부적으로 `state.frames`에 저장된다.

### 자동 추정

자동 추정은 전체 이미지 크기를 기준으로 일반적인 프레임 크기 후보를 비교한다.

현재 우선 후보:

```text
32, 48, 64, 96, 128, 24, 16, 256
```

자동 추정은 완벽한 이미지 분석이 아니라, 전체 시트 크기에 잘 나누어 떨어지는 후보를 고르는 방식이다. 따라서 실제 사용에서는 자동 추정 후 행/열과 프레임 크기를 수동 조정할 수 있어야 한다.

### 출력 순서

현재 개발 방향은 `분할된 프레임` 목록보다 `출력 순서` 중심이다.

- 분할 후 전체 프레임이 출력 순서에 자동 배치된다.
- 출력 순서에서 프레임을 선택한다.
- Shift/Ctrl/Cmd 클릭으로 다중 선택한다.
- 전체 선택, 선택 해제, 선택 추가, 전체 추가, 선택 제거, 출력 비우기를 지원한다.
- 드래그 앤 드롭 또는 앞으로/뒤로 버튼으로 순서를 조정한다.

### 위치 보정

프레임별로 원본 이미지에서 샘플링할 위치를 보정한다.

- `frameShifts`에 프레임 ID별 `x/y` 보정값을 저장한다.
- 선택한 여러 프레임에 동시에 적용할 수 있다.
- 재생, 미리보기, PNG 출력은 모두 보정된 위치를 기준으로 처리해야 한다.

### 프레임 박스 크기 보정

프레임 자체의 박스 크기를 프레임별로 변경한다.

- `frameSizes`에 프레임 ID별 `w/h` 보정값을 저장한다.
- 너비/높이를 늘리거나 줄일 수 있다.
- 전체 선택 후 한 번에 적용할 수 있다.
- 원본 이미지 바깥으로 확장된 영역은 투명 배경 또는 선택 배경색으로 처리한다.
- 출력 PNG는 확장된 프레임 박스 크기를 기준으로 셀 크기를 확장해야 한다.

중요 원칙:

- 프레임 박스 크기 보정은 원본 이미지 경계에 의해 제한되면 안 된다.
- 원본 밖 영역은 잘라내지 않고 빈 영역으로 보존해야 한다.
- 끝 열/끝 행 프레임도 전체 선택 시 동일한 크기로 확장되어야 한다.

### 가운데 정렬

선택한 프레임의 실제 픽셀 영역을 기준으로 가운데 정렬한다.

지원:

- 좌우 가운데
- 상하 가운데
- 전체 가운데

현재 방식:

- 투명 배경은 알파값으로 실제 픽셀 영역을 탐지한다.
- 단색 배경은 프레임 네 모서리 색상을 배경 후보로 보고 유사 색상을 제외한다.

주의:

- 배경과 캐릭터 색이 비슷하면 정확도가 떨어질 수 있다.
- 복잡한 배경 이미지에서는 자동 정렬 결과가 기대와 다를 수 있다.

### 미리보기와 재생

- 선택한 프레임을 확대해서 보여준다.
- 프레임 테두리와 중앙선을 표시할 수 있다.
- 재생은 출력 순서 기준으로 진행된다.
- 위치 보정과 프레임 박스 크기 보정이 반영되어야 한다.

### PNG 내보내기

- 출력 순서 기준으로 새 스프라이트 시트를 생성한다.
- 내보내기 열 수를 설정할 수 있다.
- 배경색 또는 투명 배경을 선택할 수 있다.
- 원본 오프셋/간격 유지 옵션이 있다.
- 프레임별 크기가 다를 수 있으므로, 현재 출력 프레임 중 가장 큰 박스 크기를 셀 크기로 사용한다.

## 4. 개발 원칙

### 4.1 기존 기능을 임의로 제거하지 않는다

사용자가 이미 쓰고 있는 기능은 유지한다.

예를 들어 다음 기능은 새 기능을 추가해도 계속 살아 있어야 한다.

- 선택 추가
- 전체 추가
- 선택 제거
- 출력 비우기
- 전체 선택
- 선택 해제
- 재생/정지
- 앞으로/뒤로 이동
- PNG 내보내기

기능을 제거하거나 UI에서 숨겨야 할 경우에는 반드시 이유를 명확히 하고, 대체 흐름이 있는지 확인한다.

### 4.2 출력 순서가 실제 작업 중심이다

현재 편집 흐름은 출력 순서를 중심으로 한다.

- 사용자는 출력 순서에서 프레임을 선택한다.
- 출력 순서에서 다중 선택한다.
- 출력 순서에서 위치/크기 보정을 적용한다.
- 재생과 PNG 출력은 출력 순서를 기준으로 한다.

### 4.3 보정값은 원본 프레임 데이터와 분리한다

기본 분할 프레임은 유지하고, 보정값은 별도 맵으로 관리한다.

- 기본 프레임: `state.frames`
- 위치 보정: `state.frameShifts`
- 크기 보정: `state.frameSizes`
- 출력 순서: `state.outputFrameIds`
- 선택 상태: `state.selectedFrameIds`

이 구조를 지켜야 되돌리기, 초기화, 다중 선택, 출력 재구성이 쉬워진다.

### 4.4 원본 밖 프레임 확장을 허용한다

프레임 박스 크기 보정은 원본 이미지의 오른쪽/아래 경계에 막히면 안 된다.

예시:

- 전체 선택 후 너비를 +4px 하면 끝 열 프레임도 동일하게 +4px 되어야 한다.
- 원본 밖으로 나간 영역은 투명 또는 배경색으로 남아야 한다.
- PNG 출력도 그 확장 크기만큼 커져야 한다.

### 4.5 캔버스 좌표와 CSS 표시 크기를 혼동하지 않는다

모바일에서는 캔버스가 CSS로 축소되어 보일 수 있다.

따라서 터치/클릭 좌표를 계산할 때는 다음을 고려해야 한다.

```text
canvas internal size != canvas CSS displayed size
```

현재 방식은 `getBoundingClientRect()`와 실제 캔버스 크기의 비율을 이용해 좌표를 보정한다.

### 4.6 정적 웹 환경을 유지한다

현재 편집기는 Cloudflare Pages에서 빌드 없이 배포하는 것을 목표로 한다.

따라서 다음을 지킨다.

- Node.js 빌드 과정에 의존하지 않는다.
- 번들러 없이 동작한다.
- 브라우저 표준 Web API만 사용한다.
- 외부 CDN 의존을 최소화한다.
- 모듈 시스템 없이 `<script defer>` 로딩 순서를 명확히 관리한다.

### 4.7 모바일 사용성을 항상 확인한다

모바일에서 특히 중요한 부분:

- 출력 순서가 설정한 원본 열 수 그대로 보여야 한다.
- 6열로 나누면 출력 순서도 6열로 보여야 한다.
- 버튼이 줄바꿈되어도 의미가 깨지면 안 된다.
- 방향키 패드는 항상 방향키 형태를 유지해야 한다.
- 프레임 카드가 너무 커져 행/열이 무너지면 안 된다.

## 5. 현재 알려진 주의사항

### 5.1 `app.js`가 커지고 있다

현재 `src/app.js`에 많은 기능이 집중되어 있다.

장기적으로는 다음처럼 분리하는 것이 좋다.

```text
src/
├─ app.js              # 초기화와 이벤트 연결
├─ state.js            # 상태 구조와 유틸
├─ slicing.js          # 프레임 분할/자동 추정
├─ frame-adjust.js     # 위치/크기 보정
├─ render.js           # 캔버스 렌더링
├─ export-png.js       # PNG 내보내기
└─ grid-layout.js      # 출력 순서 그리드 레이아웃
```

단, 현재는 빠르게 기능을 검증하는 단계이므로 대규모 리팩터링은 기능 안정화 후 진행한다.

### 5.2 `frame-box-fix.js` 역할 정리가 필요하다

`frame-box-fix.js`는 과거 프레임 박스 크기 보정 문제를 해결하기 위한 보조 파일이다.

현재 본체 `app.js`에 동일한 방향의 로직이 들어갔다면 다음 중 하나를 선택해야 한다.

- 중복이면 삭제한다.
- 별도 패치 파일로 계속 쓸 경우 `index.html`에서 명시적으로 로드하고 역할을 문서화한다.
- 가장 좋은 방향은 `frame-adjust.js`로 정식 분리하는 것이다.

### 5.3 자동 가운데 정렬은 완벽하지 않다

가운데 정렬은 픽셀 탐지 기반이므로 다음 경우에는 수동 보정이 필요할 수 있다.

- 배경색과 캐릭터 색이 비슷한 경우
- 그림자나 이펙트가 캐릭터보다 크게 퍼진 경우
- 프레임 안에 여러 객체가 있는 경우
- 배경이 단색이 아닌 경우

따라서 자동 정렬은 보조 기능으로 보고, 최종 조정은 상하좌우 보정 버튼으로 한다.

## 6. 배포

현재 구조는 Cloudflare Pages에 바로 배포할 수 있다.

권장 설정:

```text
Framework preset: None
Build command: 비워두기
Build output directory: /
Root directory: /
```

캐시 문제를 줄이기 위해 `index.html`에서 CSS/JS를 로드할 때 쿼리 버전을 올린다.

예시:

```html
<link rel="stylesheet" href="styles.css?v=21">
<script src="src/app.js?v=21" defer></script>
```

기능을 수정한 뒤에는 버전 값을 올려 모바일 브라우저와 Cloudflare 캐시 영향을 줄인다.

- [ ] PNG 출력에 위치 보정이 반영된다.
- [ ] PNG 출력에 프레임 박스 크기 보정이 반영된다.
- [ ] 배경색이 PNG에 적용된다.
- [ ] 투명 배경 PNG가 출력된다.

### 모바일

- [ ] 출력 순서가 설정 열 수 그대로 보인다.
- [ ] 6열 설정 시 6열이 5열로 줄어들지 않는다.
- [ ] 방향키 패드가 깨지지 않는다.
- [ ] 주요 버튼을 누를 수 있다.
- [ ] 원본 캔버스 터치 좌표가 크게 어긋나지 않는다.

## 8. 앞으로의 개발 방향

### 우선순위 높음

1. `app.js` 기능 분리
2. 프레임 크기 보정 로직 안정화
3. 출력 순서 다중 선택 UX 개선
4. 모바일 터치/스크롤 UX 개선
5. 자동 추정 정확도 개선

### 우선순위 중간

1. Undo/Redo 지원
2. 프로젝트 설정 JSON 저장/불러오기
3. 프레임별 이름 또는 태그 추가
4. 키보드 단축키 지원
5. 선택 영역 복사/붙여넣기

### 우선순위 낮음

1. 드래그로 프레임 박스 크기 조절
2. 프레임별 배경색 표시
3. GIF/APNG 미리보기 내보내기
4. 여러 이미지 파일 일괄 처리

## 9. 수정 시 주의할 점

- 사용자가 요청하지 않은 기능 삭제 금지.
- 버튼 ID를 바꾸면 `app.js` 이벤트 연결도 함께 확인한다.
- `index.html`에서 JS/CSS 버전을 올렸는지 확인한다.
- 모바일에서 6열이 5열로 줄어드는 회귀를 조심한다.
- 출력 PNG는 보이는 미리보기와 다르면 안 된다.
- 프레임 박스 크기가 원본 밖으로 확장되는 경우를 항상 테스트한다.
- 끝 열/끝 행 프레임은 경계 조건 버그가 자주 생기므로 별도로 테스트한다.
